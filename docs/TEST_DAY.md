## A. GET IT ON THE HEADSET (PowerShell, on your PC)

### Path 1 — build locally (recommended: also runs the one-time bakes)
Quest plugged in, developer mode on, Unity closed:

```powershell
cd C:\Ziptide
git pull --rebase origin terry-local-wip

# 0. (one-time, ~2 min) git merge safety — see runbook §2l:
$uy = "C:\Program Files\Unity\Hub\Editor\2022.3.62f3\Editor\Data\Tools\UnityYAMLMerge.exe"
git config --global merge.unityyamlmerge.name "Unity SmartMerge"
git config --global merge.unityyamlmerge.driver "`"$uy`" merge -p `"%O`" `"%B`" `"%A`" `"%A`""

# 1. Snapshot (sanity: branch/commit/scenes):
.\tools\ziptide_snapshot.ps1

# 2. Build + install to the Quest (regenerates ALL worlds/data, runs the audit gates, installs):
.\tools\dev_build_install.ps1

# 3. After playing — pull the smoke log (ZIPTIDE: tags):
.\tools\quest_smoke.ps1
```

If the build FAILS with `AUDIT_FAIL`, that's the quality gates doing their job — send me the
blocker lines from the log; do not sideload a red build.

### Path 2 — no local build: the CI artifact (a run is already dispatched and baking)
1. Open GitHub → **Actions → CI** → the newest `workflow_dispatch` run on `terry-local-wip` → wait
   for green (~30 min) → download the **`ziptide-apk`** artifact (zip).
2. Unzip, then:
```powershell
adb install -r .\Ziptide.apk
# watch live logs while playing:
adb logcat -s Unity | Select-String "ZIPTIDE:"
```

### One-time Unity clicks still open (unlocks spec-driven editing — 1 minute)
Open the project in Unity once → **`Ziptide → Worlds → Export All World Specs (JSON)`** → then:
```powershell
git add docs/worldspecs; git commit -m "world specs exported"; git push
```
From then on "change a world" = edit its `.spec.json`. (Runbook §2k.)
